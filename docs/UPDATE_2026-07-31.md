# 2026-07-31 整合版更新说明

维护者：by yjc

本版本以原有投递系统为主入口，整合新的 PDF 简历读取、加密归档和候选人档案系统；保留原有模型 API、岗位搜索、推荐、润色、人机交互、通知与投递编排能力。

## 主要更新

- 新增 PDF 简历分层提取、质量检查和提取记录复用，归档后不再为每次润色重复读取 PDF。
- 新增候选人档案及独立版本管理，支持从新 PDF 选择字段增量更新、手动编辑、新建版本、切换版本和受约束删除。
- 新增 SQLite 可靠状态存储、内容寻址文件资源、AES-GCM 文件加密和 Windows DPAPI 主密钥保护。
- 每次投递会话固定绑定候选人档案版本，后续档案修改不会静默改变已启动的申请。
- 将新档案内核接入原有搜索、推荐、润色和投递链路，替换旧的个人信息 JSON 与 `resume_text_cache.json` 长期事实来源。
- 保留原有 WebUI 正式入口，同时提供候选人档案管理和任务诊断界面。
- 移除腾讯文档相关主流程，优先保证单公司、单岗位的最小投递路径。

## 架构与数据层

- 新增 `core`、`application`、`infrastructure`、`api_v2`、`resume_ingestion` 和 `browser_runtime` 分层，逐步把可靠状态与原 Agent 编排解耦。
- 新增数据库迁移机制以及候选人档案、档案版本、文件资源、简历提取、职位申请、浏览器任务和审计事件等持久化模型。
- 候选人档案采用不可原地覆盖的版本模型；新 PDF 或人工编辑先形成字段级变更提案，用户确认后再创建新版本。
- 被职位申请引用的档案版本受到保护，避免删除后破坏历史申请的可追溯性。
- 新增职位申请状态机，区分准备、审核、等待用户提交、已提交、失败和结果未知，避免将“点击过按钮”误记为成功。
- 新增追加式审计事件，为后续定位页面导航、人工接管和提交结果提供依据。

## API 与 WebUI 整合

- 保留原 WebUI 的会话、WebSocket、人机交互、通知、记忆和 Agent 设置 API，并挂载新的 `/api/v2` 档案与申请 API。
- 原 WebUI 恢复为 `/` 正式入口；React 任务页保留在 `/app`，用于档案管理和辅助诊断。
- 新增候选人档案列表、PDF 提取审核、字段级增量更新、版本切换、编辑建版和删除/归档操作。
- 投递任务创建时必须选择有效档案版本；服务将加密 PDF 临时解密为本次浏览器会话可上传的文件，并在会话结束时清理。
- Agent API 设置改为当前进程内临时保存，验证成功后才用于投递，不把密钥持久化进仓库或本地设置文件。
- 增强 WebUI 事件与日志输出，补充润色分阶段耗时、登录/表单状态、页面地址、已填字段和未识别字段信息。

## 浏览器与投递流程修复

- 使用持久化受管 Chromium 保存登录状态，并明确要求用户只在系统弹出的同一浏览器窗口中登录。
- 修复登录后丢失岗位页面、错误返回岗位列表、重复打开页面及过早关闭浏览器等导航问题。
- 保存选中岗位的名称与详情链接，登录后优先恢复对应岗位，再尝试进入申请表单。
- 有头浏览器取消固定 viewport，使用可调整窗口，改善底部内容不可见和页面无法滚动的问题。
- 进入申请表单后上传一次已绑定简历，并增强对原生输入框、自定义下拉框、组合框和动态区块的扫描。
- 最终不可逆提交保留给用户本人；只有出现可验证回执才记录为成功，否则记录为失败或结果未知。

## 搜索、岗位选择与会话修复

- 保留原有按公司运行子 Agent、岗位搜索、推荐、志愿选择和人工确认流程。
- 增强搜索结果中的岗位名称、详情地址和申请地址保存，减少登录或润色后无法回到已选岗位的问题。
- 修复岗位申请按钮点击后过早回退到列表、弹窗页面识别过晚以及多个页面竞争成为当前页面的问题。
- 增加会话中断、继续、用户补充消息和人工请求状态处理，避免润色审核结束后会话被误判为完成。
- 外部模型仍负责岗位分析、推荐与润色，但候选人事实统一来自用户确认的档案版本。

## 简历润色修复

- 润色统一读取当前会话绑定的候选人档案版本和已归档的简历提取记录。
- 拆分岗位分析、简历生成和整体流程超时，避免单一短超时导致润色阶段直接终止。
- 去重模型输入，限制生成规模，并修复结构化模型结果以 JSON 字段名和括号直接显示在审核框的问题。
- 增加空结果保护和可诊断日志，避免读取失败时仍展示伪造或空白润色内容。

## 安全与运行

- 模型 API 密钥只保存在当前进程内，不写入项目配置文件。
- 候选人档案、简历正文和文件均作为敏感本地数据处理。
- 新增安全的一键启动脚本 `start_findjob.bat`；脚本不会下载文件、修改安全设置、自动打开浏览器或执行 PowerShell。
- 服务默认只监听 `127.0.0.1`。

## 已知限制

- 真实飞书招聘页面的动态表单结构会因公司模板变化。目前基础信息及第一段教育、工作和项目经历已接入确定性预填，但部分自定义控件、重复经历区块和站点动态生成字段仍可能无法正确映射。
- 当前版本尚不能宣称真实招聘站点的完整端到端投递已经稳定跑通；建议先单公司、单岗位运行，并在最终提交前人工检查所有字段。
- 人工接管记录目前只生成不包含字段值的候选定位信息，不会自动训练模型；规则必须经用户审核后才能复用。
- 复杂表单的字段标签、重复分组和自定义控件仍需要按真实页面继续完善平台适配规则；当前版本先作为可继续开发和人工验证的整合基线。
- 仓库包含重构阶段与重新整合原系统阶段留下的测试资产；最终推送前按用户要求停止继续运行和修正测试，不将其描述为完整验收通过。

## 验证状态

- 核心档案、版本、加密文件、简历提取、状态机和 API 路径已建立自动化测试。
- 浏览器适配器已通过本地模拟招聘站验证。
- 真实飞书招聘表单仍需按公司模板进行人工烟雾测试，表单预填兼容性属于当前已知问题。
