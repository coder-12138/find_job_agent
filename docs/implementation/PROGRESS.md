# 重构实施进度

更新时间：2026-07-31

## 已完成

### 阶段 0：保护现场与建立骨架

- 保留并绕开实施前已有的脏工作树修改，没有重置或回退用户内容。
- 建立隔离的 `core`、`application`、`infrastructure`、`api_v2` 与 React 任务界面。
- 建立带校验和漂移检测的 SQLite 迁移运行器。
- 服务只默认监听 `127.0.0.1`，不开放任意来源 CORS。
- 建立本地模拟招聘站，显式建模成功、失败和结果未知。

### 阶段 1：PDF、加密档案和版本管理

- PDF 原文件使用 SHA-256 内容寻址和 AES-GCM 加密；Windows DPAPI 保护主密钥。
- 文本层优先提取，质量不足时本机 RapidOCR 回退。
- 字段证据保留页码、文本片段、归一化位置、方式和置信度。
- 候选人档案字段独立加密；已确认版本不可原地覆盖。
- 更新 PDF 生成字段级变更提案，用户可只接受部分字段形成独立版本。
- 支持版本切换、归档和安全删除；被申请引用的版本禁止删除。
- 档案写操作使用乐观并发控制，变更提案接受在单个事务内完成。

### 阶段 2：职位申请聚合与状态机

- 首个正式平台白名单限定为 `jobs.feishu.cn`。
- 持久化职位快照、固定档案版本、原始简历材料、表单快照、浏览器任务和提交回执。
- 状态转换不可跳步；陈旧命令返回冲突，不静默覆盖。
- 只有可验证回执能进入 `submitted`，否则明确记录为 `outcome_unknown` 或 `failed`。
- 关键操作写入追加式审计事件。

### 阶段 3–4：受管浏览器与飞书适配器

- 进程内单一浏览器协调器拥有独立持久 Chromium 档案。
- 用户必须在弹出的受管窗口登录，登录状态可跨服务重启复用。
- 适配器只导航、识别和填入已核对字段，代码中没有最终提交动作。
- 原始加密 PDF 以内存载荷上传到表单，不写临时明文文件。
- 人工操作只生成不含字段值的候选定位提示；必须经用户批准才能复用。
- 真实 Chromium 已在本地模拟站跑通人工登录、填表、人工最终提交和回执识别。

### 阶段 5：生产切换与删减

- 根路径已切换为 React 任务界面。
- 生产 FastAPI 只挂载 v2 命令/查询 API；旧 REST 会话、WebSocket 聊天控制器和旧静态页面不再挂载。
- 腾讯文档解析模块和对应测试已删除；兼容调用显式返回“已移除”。
- LangChain、模型 API 和旧 Agent 依赖移入可选 `legacy-agent` extra，主流程不要求模型密钥。
- README、环境示例、安装和实际烟测步骤已按新闭环重写。
